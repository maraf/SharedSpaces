## Bug Fix: JWT MapInboundClaims

**Issue:** Transfer endpoint always returned 400 "Invalid destination token: missing or invalid member ID"

**Root Cause:** `JwtSecurityTokenHandler` instantiated with default `MapInboundClaims = true`, which maps JWT standard names to .NET claim types. Endpoint tried reading `JwtRegisteredClaimNames.Sub` which had been renamed to `ClaimTypes.NameIdentifier`.

**Fix:** Set `MapInboundClaims = false` in handler instantiation (line 527) to match configuration in `JwtAuthenticationExtensions.cs`.

**Justification:** Not a pre-existing bug in unrelated code — this bug prevents the new transfer endpoint from functioning at all. Directly coupled to Issue #135 implementation.
