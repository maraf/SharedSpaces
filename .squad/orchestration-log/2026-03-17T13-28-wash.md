### The Shadow DOM + Tailwind Problem

This is a **critical friction point** for SharedSpaces. Lit's Shadow DOM encapsulation breaks Tailwind's utility-first model:
- Utility classes don't penetrate Shadow DOM
- Variables (colors, spacing) unavailable inside shadow roots
- Workarounds: Dual `:root, :host` hacks, extract styles to `.css` files, runtime Twind overhead, or abandon Shadow DOM
- React: Zero config, Tailwind works out-of-the-box

### Development Perspective

Wash highlighted the **reality of shipping alone** (single frontend dev on a small project):
- React ecosystem lets devs move fast, copy-paste patterns, focus on features users care about
- With Lit, developer wastes 30% of time fighting tooling and researching patterns
- Stack Overflow: 10x more React + SignalR examples than Lit + SignalR
- When a weird bug appears, Lit developer is on their own; React developer finds answers instantly

### When Lit Would Make Sense

Acknowledged Lit's strengths for specific use cases **not applicable** to SharedSpaces:
- Design systems (reusable components across frameworks)
- Microfrontends (framework-agnostic widgets)
- Extreme bundle size constraints (embedded widgets on third-party sites)
- Teams with deep Lit expertise already
