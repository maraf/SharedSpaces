## Phase: UX Trade-Offs Analysis (Completed)

**Objective:** Analyze action button consolidation options and provide architectural recommendation for Issue #152.

**Analysis Scope:**
- Evaluated 4 design variants proposed by Wash
- Ranked by action frequency, mobile constraints, and accessibility
- Assessed desktop vs. mobile UX consistency
- Identified implementation complexity vs. user benefit trade-offs

**Key Trade-Offs Evaluated:**
1. **Discoverability vs. Space Efficiency**
   - Kebab menu: Visible affordance (three-dot icon) + hidden actions
   - Swipe-to-reveal: Zero affordance, maximum content space
   - Long-press: Zero affordance, mobile-native but uncommon in web
   - Bottom sheet: All actions available but modal friction

2. **Complexity vs. User Experience**
   - Kebab menu: Medium complexity, familiar pattern, single extra tap for secondary actions
   - Swipe: High complexity, gesture conflicts, accessibility challenges
   - Long-press: Medium complexity, discovery issues, slow interaction
   - Bottom sheet: Medium-high complexity, buries primary actions

3. **Desktop Consistency**
   - Kebab menu: Responsive breakpoint (all visible on desktop)
   - Other variants: Force desktop/mobile split or inconsistent behavior

**Recommendation:** Responsive Kebab Menu on Mobile (<640px)
- Primary action (Copy/Download) remains one tap
- Secondary actions (Manage Links, Send To, Delete) in dropdown
- Desktop behavior: Unchanged (all buttons visible)
- Clear progressive disclosure pattern

**Rationale:**
- Minimizes cognitive overhead on mobile without sacrificing desktop UX
- Responsive breakpoint is clean and maintainable
- Familiar affordance (three dots) reduces learning curve
- ~72px space savings (3 buttons @ ~36px each → kebab icon)
- Supports future action additions without UI bloat
