**Topic:** Research Issue #161 (share link missing API URL)

## Outcome

- Identified root cause: Static meta tag hardcoded to "/" blocks multi-domain deployments
- Proposed 3 options for API URL handling
- Recommended Option A: Embed server URL in SharedLink entity

## Findings

### Root Cause
- `SharedLink` entity lacks server URL context
- Current meta tag uses hardcoded "/" prefix
- Cannot resolve API calls on non-root deployments

### Options Evaluated

1. **Option A (Recommended):** Add API URL to SharedLink entity
   - Pros: Centralized, backward compatible
   - Cons: Storage overhead (URL per link)

2. **Option B:** Query parameter (e.g., `?apiBase=...`)
   - Pros: No storage changes
   - Cons: User-visible, potential abuse

3. **Option C:** Server routing (reverse proxy)
   - Pros: Transparent to client
   - Cons: Requires infrastructure changes

## Decision Input

- Leaning toward Option A for simplicity and robustness
